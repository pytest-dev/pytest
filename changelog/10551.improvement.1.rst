The logging plugin's options are now declared with :func:`parser.addconfig()
<pytest.Parser.addconfig>`, which changes three things for the better:

* The configuration options are now typed. ``log_file_mode`` is restricted to
  ``w`` and ``a``, matching what ``--log-file-mode`` always accepted, so
  ``-o log_file_mode=q`` is an error rather than silently accepted. The three
  level options accept an integer or a string, and ``log_auto_indent`` a
  boolean, an integer or a string.
* ``log_cli_*`` and ``log_file_*`` now fall back to their ``log_*``
  counterparts through the registered ``fallback``. **This changes behaviour**:
  the previous lookup tested truthiness, so an explicitly configured empty
  value such as ``log_cli_format =`` fell through to ``log_format``. It is now
  honoured as the configured value it is.
* Each option's help text describes the option, rather than being generated as
  ``"Default value for --log-cli-format"``.

``log_cli`` gains a ``--log-cli`` command line flag, which previously could
only be enabled from a configuration file or indirectly via
``--log-cli-level``.
