Captured ``sys.stdout`` and ``sys.stderr`` now preserve the encoding and error handler of the streams they replace. Their ``.encoding`` and ``.errors`` attributes reflect the settings used for text writes, so text the original stream cannot encode follows its error handler. With ``strict``, this raises ``UnicodeEncodeError`` while capture is active, just as it does with ``-s``. On Windows before Python 3.15, where piped output commonly uses ``cp1252`` with ``strict``, tests that print characters such as ``✓`` can therefore start failing when capture is enabled. Bytes written directly through ``.buffer`` are decoded using the stream's encoding when captured output is read back. With ``surrogateescape``, undecodable bytes are preserved; with ``surrogatepass``, surrogate code points are preserved and other undecodable bytes are replaced. For other error handlers, undecodable bytes are replaced.
