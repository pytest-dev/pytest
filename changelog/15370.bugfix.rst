:class:`~pytest.mark.parametrize` marks with explicit ``ids`` shared by several tests (for example, when the mark is put on a class) no longer escape the ids a second time when the cached ids are reused. Previously, every test after the first sharing the mark got different node ids, making those tests impossible to select by their ``ids`` value and breaking tools that reuse node ids across repeated :func:`pytest.main` calls in one process.
