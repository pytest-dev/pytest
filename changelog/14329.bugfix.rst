:meth:`~_pytest.nodes.Node.iter_markers` and :meth:`~_pytest.nodes.Node.get_closest_marker`
now walk the class MRO closest-first, so a marker on a subclass takes precedence over the
same marker on one of its base classes. This includes :ref:`skipif <pytest.mark.skipif ref>`
and :ref:`xfail <pytest.mark.xfail ref>`: a subclass' mark now decides, where previously the
base class' did, for example a base class' ``strict=True`` no longer applies when the
subclass has its own ``xfail``.

``own_markers`` keeps its previous (base class first) order, and so do the consumers that
compose markers rather than look one up: :ref:`usefixtures <usefixtures>` fixtures are still
requested in the same order as before, inherited class level
:ref:`parametrize <pytest.mark.parametrize ref>` markers still compose their test IDs the
same way, and a subclass' :ref:`filterwarnings <pytest.mark.filterwarnings ref>` still takes
precedence over its base class'.
