Fixed duplicate log records when a logger which was non-propagating at capture
start enables ``logging.Logger.propagate`` during the test: the record was
handled both by pytest's handler attached directly to that logger and by the
one attached to the root logger. Capture (``caplog``, failure-report sections,
``--log-cli-level`` and ``--log-file`` output) now sees each record exactly
once, and the previously-missed ``True -> False`` transition on the affected
loggers and their ancestors is now handled as well.

The handler standing in for a capture handler on those loggers is now also
attached and detached by identity rather than by equality, so a user handler
which compares equal to one of pytest's own is no longer removed in its place,
and two loggers sharing one ``handlers`` list are handled correctly. It no
longer holds its own lock while forwarding, which could deadlock against the
real handler's lock. Filters and formatters installed through such a handler
keep applying while the logger is non-propagating and are removed again when
capture ends, and a failure during capture setup no longer leaves pytest's
handler attached to the root logger.
