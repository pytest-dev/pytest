``WarningsRecorder.pop()`` (and therefore ``pytest.warns().pop()`` and ``recwarn.pop()``) again returns the first recorded warning when the recorded warning categories are unrelated to each other.

Since pytest 8.0 a later, unrelated category could replace the current best match, so popping from a list of e.g. a :class:`UserWarning`, a :class:`RuntimeWarning` and a :class:`DeprecationWarning` returned the last one. The documented behaviour -- the first match which is not a child class of any other match -- is restored.
